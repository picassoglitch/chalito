# Deviations from the brief

When the brief and the current docs disagree, the docs win (brief §1, "Verify APIs before coding against them"). Every deviation is recorded here with its reason and source. Sources are in `docs/VERIFIED_APIS.md` (checked 2026-10-03).

| ID | Brief says | We do | Why / source | Milestone |
|---|---|---|---|---|
| D-001 | Codename "Director", label "Chalyb Partner" | **Chalito** everywhere: `chalito-agent`, `chalito` CLI, `~/.chalito/`, `@chalito/*`, credit line "`<Name> · powered by Chalito Bot`" | Brief instruction; ADR 0000 | M0 |
| D-002 | Claude Code BYO may use the user's subscription login "if re-verified OK" | **API key only** (or a cloud-provider credential). The env is pinned (`ANTHROPIC_API_KEY` in `options.env`) so the CLI never falls back to `/login`. We never read `~/.claude/.credentials.json`. | The Agent SDK docs say: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK." The legal page's "unmodified binary" carve-out is ambiguous for SDK-driven use. Decision #19 resolves to its safe default; owner may ask Anthropic for approval. | M3 |
| D-003 | Codex runs under the user's own login ("Sign in with ChatGPT"), confirm enrollment (OPS) | **Codex BYO = API key** by default. The ChatGPT-plan path (SIWC) stays behind `providers.yaml: openai.subscriptionLocal: false` until OpenAI approves Chalito as a commercial partner. | "App-server authentication has never been permitted for commercial or hosted services." SIWC for paid apps is waitlist-gated, and only Plus/Pro users can spend their plan. New decision #26. | M4 |
| D-004 | Permission modes: highest remote = `acceptEdits`; never `bypassPermissions` | Same ceiling, and also `dontAsk` and `auto` are unrepresentable remotely (`RemotePermissionMode = default \| plan \| acceptEdits`). The adapter always passes `permissionMode: 'default'` explicitly, sets `settingSources: ['project']` by default, and uses a PreToolUse hook with `timeout` > 600 s. | The SDK now has 6 modes. Omitting the mode may resolve to `auto` (≥0.3.286). `canUseTool` doesn't fire for auto-approved calls. The PreToolUse default timeout is 600 s and a timeout means the tool doesn't run. | M3 |
| D-005 | Agent ships "service installers for launchd, **Windows Service** and systemd user units" | Windows uses a **per-user Scheduled Task** (logon trigger, restart on failure), falling back to `HKCU\…\Run`. **No Windows Service.** | A Windows Service runs as LocalSystem and can't read the user's Credential Manager (where BYO keys and agent keys live). ADR 0004. | M3/M14 |
| D-006 | Pet window click-through "by hit-box/alpha test"; Linux X11, Wayland best effort | Hit-testing by **polling `cursorPosition()`** against the avatar bounds/alpha mask and toggling `setIgnoreCursorEvents`. On Linux the pet window runs under **XWayland** (`GDK_BACKEND=x11`). | Tauri exposes no per-pixel hit-test. `cursorPosition()` returns (0,0) on native Wayland, and always-on-top is ignored by most Wayland compositors. | M7 |
| D-007 | E2E: "plaintext egress none" | Managed brains (companion, Mesa) see plaintext **transiently in memory** in `api`/`orchestrator` on the way to the provider. Nothing is persisted, and stored turns are sealed. In Private mode with BYO keys, the companion can call the provider straight from the device. | A server-side LLM call needs plaintext. ADR 0003, THREAT_MODEL §4.6. Disclosed in the privacy policy. | M9 |
| D-008 | Agent uses `@anthropic-ai/claude-agent-sdk` in a single executable | The SDK spawns a ~245 MB native `claude` binary (no more `cli.js`). By default the agent uses the **user's installed Claude Code** via `pathToClaudeCodeExecutable`; onboarding links to Anthropic's installer. Bundling is new decision #21. | SDK 0.3.288 packaging; keeps Claude Code unmodified and sourced from Anthropic; avoids redistributing it. ADR 0004. | M3 |
| D-009 | Code fails closed on `mirror_matching_tier` | **Managed allowance** fails closed (disabled, "Disponible pronto"). **Count inclusions** (devices, sessions, rooms, members, voice/calls/WhatsApp) are **not enforced** while unset. Daily comms caps (calls 3, WhatsApp 10) and rate limits still apply. | Failing closed on counts would mean 0 devices and an unusable beta, and inventing interim numbers is forbidden (§12). Decision #1 lists both. | M12 |
| D-010 | Device agent: "a single-executable build per OS" (Node 22) | **`bun build --compile`**, with `@yao-pkg/pkg` as the fallback. Not Node SEA. | Node 22 SEA is Stability 1.1 and CommonJS-only. The Agent SDK documents a bun-compile path. ADR 0004. | M3 |
| D-011 | Release secrets `APPLE_APP_SPECIFIC_PASSWORD`, "Azure Trusted Signing" | `APPLE_PASSWORD` (holds the app-specific password), or preferably App Store Connect API keys (`APPLE_API_ISSUER`, `APPLE_API_KEY`, `APPLE_API_KEY_PATH`). Windows signing via **Azure Artifact Signing** (renamed). | Tauri 2.12 env var names; Microsoft rename. EV certificates no longer bypass SmartScreen (2024). ADR 0014. | M14 |
| D-012 | Cheap model "e.g. Gemini Flash-Lite on Vertex via the global endpoint … or Claude Haiku 4.5" | Router/moderator/summarizer: **`gemini-3.1-flash-lite` on the `global` endpoint**, fallback `gpt-6-luna`. Haiku 4.5 is optional, never a hard dependency. | `gemini-2.5-flash-lite` retires 2026-10-20. 3.1 Flash-Lite exists only on global and the us/eu multi-regions. Haiku 4.5 may retire after 2026-10-15 and needs ≥4,096 tokens to cache. The +10% non-global surcharge is confirmed for Gemini 3+ since 2026-07-01. | M9 |
| D-013 | WhatsApp utility templates; cost model assumed free in-window utility | Same design. The cost model counts **every** utility message (MX USD 0.0085) and pins Graph API **v26.0**. | Meta pricing change effective 2026-10-01. Unverified businesses are limited to 250 unique recipients/day, so business verification becomes an early OPS item. | M6 |
| D-014 | Call connect = "SIP bridge to an OpenAI Realtime session" | `<Dial><Sip>sip:<proj>@sip.api.openai.com;transport=tls;secure=true</Sip>` from Programmable Voice. **No Elastic SIP Trunking.** Say voices `Polly.Mia-Neural` (es-MX) and `Polly.Joanna-Neural` (en-US). `<Gather>` without `speechModel` for es-MX. | Twilio's official tutorial uses Programmable SIP; OpenAI requires TLS + SRTP. Twilio has no Google es-MX voices; the `phone_call`/`experimental_*` speech models lack es-MX. | M6 |
| D-015 | Web Push via FCM | FCM **`register()` / `onRegistered()`** with Firebase Installation IDs; HTTP v1 `fid`. | `getToken()` is deprecated, and the `token` field is deprecated in favour of `fid`. | M5 |
| D-016 | Stripe Billing with trials; `sync-billing-catalog` in "test mode"; USD with local-currency presentment | The **1-month trial is Chalito-side** (`subscriptions.trialEndsAt`, no card needed). Subscribing mid-trial uses Checkout `subscription_data.trial_end`. Catalog sync targets a **Stripe sandbox**. Local-currency presentment depends on the Stripe entity (decision #23). | The new Trial Offer API isn't supported in Checkout. An MX account settles MXN only, and Adaptive Pricing needs the price currency to be a settlement currency. OXXO/SPEI can't do subscriptions. Stripe recommends sandboxes over test mode. ADR 0012. | M12 |
| D-017 | MCP OAuth into Identity Platform | The authorization server advertises **CIMD** (preferred by both Claude and ChatGPT), with DCR kept for compatibility. Implements spec **2026-07-28** (RFC 9728/8707/9207). TS SDK v2 (`@modelcontextprotocol/server` + `/hono`). | The latest MCP revision deprecates DCR; the v1 SDK is legacy. ADR 0009. | M10 |
| D-018 | next-intl, ES unprefixed, locale from the URL only | Next.js 16 **`proxy.ts`** (formerly `middleware.ts`); next-intl `localePrefix: 'as-needed'`, `localeDetection: false`. | Next 16 renamed the convention. Without `localeDetection: false` the cookie could redirect `/` to `/en`. | M5 |
| D-019 | HIGH approvals: "biometric/WebAuthn" | We implement **WebAuthn ourselves**. The assertion challenge = SHA-256 of the decision body, and the **agent verifies it** against the credential it recorded during the local reverse check (`StepUp.assertion` in protocol). | Identity Platform has no native passkeys. Agent-side verification proves user presence to the device, not just to the cloud. | M2/M5 |
| D-020 | Region `us-central1` (default) or `us-south1` | **`us-central1`** for everything, including Firestore (decided once at bootstrap). Front door: **Firebase Hosting** for `web` + `/api`; Cloud Run domain mapping for `api.` / `mcp.`; global ALB as the prod path. | Cloud Run domain mapping (Preview) and Firebase App Hosting are not offered in us-south1. Firebase Hosting rewrites cap at 60 s, so MCP gets its own host. ADR 0015. | M2 |
| D-021 | Codex: initialize, `thread/start`, `turn/start`, `thread/resume`, approval requests | Same methods. The wire is JSONL **without** `"jsonrpc":"2.0"`. Approvals are `item/commandExecution/requestApproval` and `item/fileChange/requestApproval`, answered with `{decision: accept\|acceptForSession\|decline\|cancel}`. The Chalito side never sends `acceptForSession` (each approval is a single signed decision). The per-turn `sandboxPolicy` is a tagged object. | codex-rs app-server-protocol at 3e238776. app-server is labelled experimental, so we pin a tested version range. | M4 |
| D-022 | Grok Build over ACP (stretch) with "Grok Build own auth" | The ACP adapter uses **`XAI_API_KEY`** by default. Grok Build's own login (which draws on the user's Grok subscription) is off until xAI terms for third-party embedding are confirmed (new decision #27). | `grok agent stdio` exists, but no terms for third-party embedding were found. | M4 |
| D-023 | `packages/protocol` lists schemas; `plans.yaml` "validates against its zod schema" | The `PlansConfig` schema lives in `packages/protocol/src/plans.ts` next to `Entitlements`. "solo + Chalyb" is modelled as `line: solo` + `availableVia: [solo, chalyb]`. Bundles have no `availableVia` (not specified). Origins have **no `room:*` value**. | Keeps billing types in one place. Rooms can never originate a session turn (brief §1). | M0 |
| D-024 | macOS transparency via `macOSPrivateApi` | Not needed. It is a no-op in Tauri 2.12.1+ and the private APIs are always on. Mac App Store distribution is out of scope (DMG only). | Tauri PR #16166 (2026-09-29). | M7/M14 |
